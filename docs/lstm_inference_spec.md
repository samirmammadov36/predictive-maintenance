# Saved LSTM prefix inference

`LSTMInferenceAdapter(bundle, artifact_dir="artifacts")` loads only LSTM through `load_lstm_checkpoint()` once, including its existing architecture, selected-checkpoint, input-metadata, split/prefix provenance and checksum checks. Missing/legacy/incompatible metadata is rejected, never fabricated. The adapter keeps private copies of fitted training medians/scaler and frozen sensor order; later caller bundle changes do not alter inference. No XGBoost, Streamlit, model fitting or preprocessing fitting is required. Existing metadata validation checks declared compatibility, not independent reproduction of training/scaler statistics.

Call `adapter.predict(raw_trajectories, engine_id, observed_cycle, *, dataset_split=None, scenario="clean", recovery="median", seed=None)`. Engine ID and cutoff must be positive integers. If dataset_split exists, supply its non-empty string namespace when an engine ID occurs in multiple namespaces; a single unambiguous namespace can be inferred. Supplying a split for a frame without that column is rejected.

The boundary is engine selection, then cycle <= observed_cycle, then chronological sorting. Selected-engine cycle metadata must be valid to establish visibility. Sensor validation/processing sees only visible rows. Hidden sensor values, RUL targets, settings and unselected sensors never enter masks, recovery, scaling, sequences, predictions or chart data. Input frames are not mutated. Visible duplicate cycles/row labels, missing identities, empty prefixes, nonnumeric/infinite sensors and invalid options fail clearly; native sensor NaNs are allowed until recovery. Cutoffs between available cycles or beyond the final row return the actual last visible cycle without creating observations.

Order: raw visible prefix -> shared mask -> recovery -> saved scaling -> 30-cycle first-imputed-observation left padding -> LSTM prediction. Scenarios are clean, random_10, random_20, short_gap. Clean accepts median only. Missingness accepts median or causal within-engine forward_fill with training-median fallback. Random scenarios require seed 7/17/27; other scenarios require seed=None. Masks are generated after truncation using the existing rounding/RNG/nesting and sensor_11/frozen-first short-gap fallback. Different cutoffs do not require prefix-stable masks.

`LSTMInferenceResult` contains `rul_pred` (one finite scalar, operating cycles, clamped to zero), `engine_id`, optional `dataset_split`, `cycle` (actual final visible cycle), `observed_history_length`, `sequence_window`, `padding_cycles`, `chart_prefix`, and `sensor_mask`. Finiteness is checked before clamping, including negative infinity.

`chart_prefix` is a deep copy of **recovered, unscaled measurements** in identity/cycle/frozen-sensor order. It contains neither targets nor future rows. `sensor_mask` is a copied boolean selected-sensor mask on the same visible row indices, retained for auditing. Mutating returned frames cannot change the caller or later predictions. Chart consumers must use this bounded frame rather than the original trajectory.

Tests use temporary synthetic preprocessing/checkpoint artifacts and the actual saved RULLSTM path; they do not establish real FD001 preparation/training/evaluation. The adapter itself remains Streamlit-independent. The application connection described below adds slider-driven LSTM replay; autoplay remains separate team work; Task 25 now connects the other adapters through the shared replay/queue flow. The merged application now connects the shared top-K component to validated LSTM inference.

## Streamlit LSTM replay

Run `.venv\Scripts\python.exe -m streamlit run app.py` from the repository. `app.py` defaults to LSTM and loads `prepared_bundle.joblib`, obtains raw trajectories exclusively through `official_test_raw_frame()`, and creates the validated adapter. Missing, legacy, corrupt or incompatible artifacts show an application error; no historical/dummy predictions, automatic preparation, downloads or training are used.

Engine choices use `(dataset_split, engine_id)` when present. The observed-cycle select-slider contains only that engine's available cycles; a one-observation engine uses its single cycle without a slider. Clean fixes recovery to median and omits seed; random scenarios expose 7/17/27; other missingness supports both recovery methods without a random seed. The selected RUL, demo health label, actual cycle/history/window/padding and recovered sensor chart are displayed. Health labels use the shared display-rule note.

`build_lstm_replay()` calls the actual adapter separately for every available cycle up to the selected cutoff, including the final point. Each call creates its own truncated raw prefix, mask and recovery. It never computes later points or reuses the final recovered prefix for earlier predictions. Sensor plotting receives only `result.chart_prefix`; RUL plotting receives only these per-cutoff predictions.

Only loaded resources are cached, using the absolute artifact directory plus SHA-256 contents of the prepared bundle, sequence input metadata, split manifest, LSTM checkpoint and checkpoint metadata. Fitted medians/scaler and raw observations are consumed from the bundle. Every rerun recomputes fingerprints; changed/missing files invalidate or reject the resource cache. A change during loading is rejected. Replay results are not cached, so engine/cutoff/scenario/recovery/seed changes are recomputed. Artifacts should be published as a consistent set; the existing metadata checks do not independently authenticate scaler/median statistics.

The optional `run_app(artifact_dir=...)` argument supports deployment configuration and temporary synthetic AppTest fixtures; it is not a dataset upload or training UI. All four model controls now invoke reusable saved adapters, with top-K available for each loaded model. On request, the queue calls the validated adapter once for every engine in the selected official-test namespace at that engine's own final observed cycle, then sorts by ascending predicted RUL with engine ID as the tie-breaker for K=5/10 and offers a CSV download. All engines are predicted before selecting top-K. Final snapshot cycle lengths differ: this demonstration queue is not synchronized and is independent of the selected-engine replay slider. Each final raw engine prefix receives its own mask/recovery/scaling/window; replay and sensor/RUL charts continue to use the selected cutoff. Queue results are not cached or retained across control/artifact reruns; other-model paths follow the [saved inference contract](saved_inference_spec.md). Tests inspect actual Matplotlib line data and use synthetic saved checkpoints; real FD001 and full multi-model/queue acceptance remain unverified.

# Saved LSTM prefix inference

`LSTMInferenceAdapter(bundle, artifact_dir="artifacts")` loads only LSTM through `load_lstm_checkpoint()` once, including its existing architecture, selected-checkpoint, input-metadata, split/prefix provenance and checksum checks. Missing/legacy/incompatible metadata is rejected, never fabricated. The adapter keeps private copies of fitted training medians/scaler and frozen sensor order; later caller bundle changes do not alter inference. No XGBoost, Streamlit, model fitting or preprocessing fitting is required. Existing metadata validation checks declared compatibility, not independent reproduction of training/scaler statistics.

Call `adapter.predict(raw_trajectories, engine_id, observed_cycle, *, dataset_split=None, scenario="clean", recovery="median", seed=None)`. Engine ID and cutoff must be positive integers. If dataset_split exists, supply its non-empty string namespace when an engine ID occurs in multiple namespaces; a single unambiguous namespace can be inferred. Supplying a split for a frame without that column is rejected.

The boundary is engine selection, then cycle <= observed_cycle, then chronological sorting. Selected-engine cycle metadata must be valid to establish visibility. Sensor validation/processing sees only visible rows. Hidden sensor values, RUL targets, settings and unselected sensors never enter masks, recovery, scaling, sequences, predictions or chart data. Input frames are not mutated. Visible duplicate cycles/row labels, missing identities, empty prefixes, nonnumeric/infinite sensors and invalid options fail clearly; native sensor NaNs are allowed until recovery. Cutoffs between available cycles or beyond the final row return the actual last visible cycle without creating observations.

Order: raw visible prefix -> shared mask -> recovery -> saved scaling -> 30-cycle first-imputed-observation left padding -> LSTM prediction. Scenarios are clean, random_10, random_20, short_gap. Clean accepts median only. Missingness accepts median or causal within-engine forward_fill with training-median fallback. Random scenarios require seed 7/17/27; other scenarios require seed=None. Masks are generated after truncation using the existing rounding/RNG/nesting and sensor_11/frozen-first short-gap fallback. Different cutoffs do not require prefix-stable masks.

`LSTMInferenceResult` contains `rul_pred` (one finite scalar, operating cycles, clamped to zero), `engine_id`, optional `dataset_split`, `cycle` (actual final visible cycle), `observed_history_length`, `sequence_window`, `padding_cycles`, `chart_prefix`, and `sensor_mask`. Finiteness is checked before clamping, including negative infinity.

`chart_prefix` is a deep copy of **recovered, unscaled measurements** in identity/cycle/frozen-sensor order. It contains neither targets nor future rows. `sensor_mask` is a copied boolean selected-sensor mask on the same visible row indices, retained for auditing. Mutating returned frames cannot change the caller or later predictions. Chart consumers must use this bounded frame rather than the original trajectory.

Tests use temporary synthetic preprocessing/checkpoint artifacts and the actual saved RULLSTM path; they do not establish real FD001 preparation/training/evaluation. This adapter does not connect dashboard controls, implement replay scheduling/queues, or create charts. Those application integration and end-to-end checks remain separate work.

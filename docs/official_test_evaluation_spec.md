# Official FD001 missingness evaluation

`PreparedBundle.official_test_raw_df` stores a copy of the original observed official-test trajectories before median recovery, including native sensor NaNs. Existing `official_test_df` remains median-imputed for compatibility; training/validation preparation, fitted medians and scalers remain unchanged. The executable evaluator exclusively uses the explicit raw field. Older bundles without it fail with instructions to regenerate via `python scripts/prepare_data.py` in the project .venv using the original FD001 files; already-imputed data is never inferred to be raw.

Order: select one raw observed engine prefix, sort by cycle, apply the shared selected-sensor mask, recover, apply saved features/scaling/sequences, predict once at its final observed cycle. S0 uses training medians for native NaNs. S1/S2 use the existing nested 10%/20% masks with seeds 7/17/27, and S3 uses the final-five-cycle sensor_11 gap with the frozen-sensor fallback. Each missingness scenario uses training medians and causal forward fill. There are exactly 15 configurations per trained RF/XGBoost/LSTM model. Deterministic masks use the same raw prefix, frozen sensor order and seed across recovery methods; all models receive the same recovered frame.

The runner sorts and isolates each engine before forward fill. Initial missing values fall back to training medians, with no earlier engine, backward fill or future interpolation. No preprocessing fit, retraining or test-based tuning occurs during evaluation.

The real entrypoint `scripts/run_checkpoint_experiments.py` explicitly requires engine IDs 1..100 and exactly one finite, non-negative uncapped official label per engine, aligned to the final observed cycle. Raw rows must have unique labels and engine/cycle pairs; sensor NaNs are allowed and infinities rejected. A present dataset_split must identify one namespace and match labels when both frames contain it. Missing/extra/duplicate predictions, cycle/label mismatches, or non-finite outputs fail; finite negative predictions are clamped to zero. `expected_engine_ids` is a keyword argument for small synthetic runner fixtures; the real entrypoint does not expose an override.

LSTM metric rows retain `n_engines` and add `n_padded_engines`, `n_unpadded_engines`, `sequence_window`, and min/max observed history lengths. Predictions add final `cycle`, `observed_history_length`, `sequence_window`, `sequence_history_length` and `padding_cycles`. Every engine is retained, including histories shorter than 30; short sequences repeat the first recovered observation on the left. Existing MAE/RMSE and clean delta meanings are preserved; random seeds are aggregated with means and sample standard deviations (ddof=1), including delta MAE/RMSE.

Tests use synthetic data and temporary artifacts. They verify raw-before-recovery flow, native NaNs, shared masks, chronology/engine isolation, final-cycle scoring, uncapped labels and coverage. They do not establish real FD001 preparation/evaluation, dashboard or replay correctness. Root comparison/export utilities are outside the executable path and remain unchanged.
